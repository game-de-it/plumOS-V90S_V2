# V90S EasyRPG Standalone Launch Validation

Date: 2026-07-15

## Symptom

The frontend selected this indexed game directory:

```text
/mnt/plumos/roms/EASYRPG/TurnedIntoAGirl
```

The generated launch command passed it as a positional argument to EasyRPG
Player. The process and PowerVR SDL2 window started, but the screen reported:

```text
No games found in the current directory.
```

The live process confirmed the incorrect command contract:

```text
easyrpg-player /mnt/plumos/roms/EASYRPG/TurnedIntoAGirl
```

## Cause

EasyRPG Player 0.8.1.1 does not interpret a positional directory as the game
project. Its documented command-line interface requires:

```text
--project-path PATH
```

The frontend already converts an indexed `.ldb` file to its parent directory,
but the standalone launcher did not translate the resulting content path into
EasyRPG's command-line option.

## Fix

The generated `plumos-standalone-launch` now handles the `easyrpg` profile as
an emulator-specific contract:

- require a project path
- convert a direct `.ldb` path to its parent directory
- reject a path that is neither a directory nor a file
- execute `easyrpg-player --project-path PROJECT`

The change is generated by:

```text
docker/plumos-v90s-toolchain/scripts/build-standalone-emulators.sh
```

## Physical V90S Proof

Before changing the launcher, the corrected argument was tested directly with
the deployed EasyRPG binary. The log reported:

```text
CLI: --project-path /mnt/plumos/roms/EASYRPG/TurnedIntoAGirl
Game and Save Directory:
1: [Native] -> /mnt/plumos/roms/EASYRPG/TurnedIntoAGirl
Loading game CookieCutterTurnedIntoGirl
Resolution changed to 320x240
```

The process remained active, PowerVR SDL2 selected an ABGR8888 renderer,
`adc_gamepad` was detected, and ALSA PCM remained `RUNNING`.

The generated launcher was rebuilt and deployed as
`/mnt/plumos/bin/plumos-standalone-launch` with SHA-256:

```text
e26dac85585e4e5e33df354c26edf9509513b54e5da27a468a822d7b49d5be1e
```

Physical controls, audio, exit, and FE return still require a launch through
the normal standalone frontend profile. Do not treat the direct diagnostic
launch as that final integration proof.
